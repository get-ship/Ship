**Location**: `.ship/ship.lock`
**Format**: TOML (the one Ship config file that isn't JSONC)

Generated by `ship install`. Pins every dependency to an exact commit and content hash. Always commit this file. Do not hand-edit.

## Structure

```toml
version = 1

[[package]]
path = "github.com/acme/toolkit"
version = "1.2.0"
commit = "6a1636950a1d7fc53602639ce7505a4a5d39c797"
hash = "sha256:83fb025b015f9472ea8504cbdf8c8e042eff86f87cb0f69757bb00fbacd5acb9"
```

## Fields

| Field | Type | Description |
|-------|------|-------------|
| `version` | integer | Lock file format version. Currently `1`. |
| `path` | string | Package path (matches dependency key in ship.jsonc) |
| `version` | string | Resolved tag or branch name |
| `commit` | string | Full 40-character Git SHA |
| `hash` | string | Content integrity hash: `sha256:<hex>` |

## Content hashing

The hash is a SHA-256 of the package tree, computed deterministically:

1. Walk the file tree recursively under the package root
2. Exclude `.git/`, `ship.lock`, `.ship/state/`, `.DS_Store`, `Thumbs.db`, `.swp`
3. Sort all file paths lexicographically (forward-slash separators)
4. For each file: `<relative-path>\0<byte-length>\0<sha256-of-content>`
5. SHA-256 the accumulated string
6. Output: `sha256:<lowercase-hex>`

Per-export hashes are also computed — changing one skill's content only changes that skill's hash.

## CI usage

```bash
ship install --frozen  # Fails if ship.lock would change
```

Use `--frozen` in CI to guarantee reproducible installs. If the lock file is stale, the build fails explicitly rather than silently resolving different versions.
