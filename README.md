# Ship

**Don't just build. Ship.**

Ship is a runtime for AI agent teams. Not a harness — a runtime. It gives agents coordination primitives, compiles configuration to every provider, and lets you build multi-agent systems the way you want them.

## Compiler

One `.ship/` directory. Every provider.

- `orchestrator::emit` — re-export of the L0 `ship-runner` emit mechanism.
- `orchestrator::exit_handler` — re-export of the L1 `ship_code::runner::exit_handler`
  (harness-driver-specific exit commands). `dedup` / `router` / `DISPATCH_GATE` /
  `terminal_guard` live at L0 `ship_runner` and are imported directly from there
  as part of the seam-leak eviction.
                                     .cursor/rules + .cursor/mcp.json
                                     GEMINI.md + .gemini/settings.json
                                     AGENTS.md + .codex/config.toml
```

You commit `.ship/`. Provider configs are build artifacts — gitignored, regenerated by `ship use`.

| Provider | Context | MCP Config | Permissions |
|----------|---------|------------|-------------|
| Claude | CLAUDE.md | .mcp.json | settings.json |
| Cursor | .cursor/rules | .cursor/mcp.json | — |
| Gemini | GEMINI.md | .gemini/settings.json | — |
| Codex | AGENTS.md | .codex/config.toml | — |

```bash
ship use my-agent        # compile + write all provider files
ship compile             # compile without activating
```

## What you author

Ship gives you seven primitives. You define them in `.ship/`; the runtime makes them real.

- **Agents** — provider-portable profiles (skills, MCP servers, permissions)
- **Skills** — markdown templates compiled into agent context with progressive disclosure
- **Artifacts** — typed working files agents read and write
- **Collections** — structured, queryable data (ADRs, systems, anything you schema)
- **Pipelines** — declarative multi-step work; the runtime dispatches and routes completion
- **Views** — daemon-served UI surfaces (`.sui`, compiled to ESM on a signal-graph runtime) for inspection and authoring
- **Triggers** — event-sourced reactions that fire on runtime state changes

## Smart Skills

Skills are markdown templates compiled into agent context. They use progressive disclosure — agents attach only the skill refs they need, so a large reference doesn't bloat every context.

```jsonc
{
  "skills": { "refs": ["tdd", "code-review"] }
}
```

Skills are shareable packages. The registry at [getship.dev](https://getship.dev) hosts community skills. Built-in: `tdd`, `code-review`, `web-qa`, `browse`, `spawn-agent`, `design-review`, and more.


## Pipelines

Declarative multi-step work. You define the pipeline; the runtime dispatches steps in order and routes completion signals.

```yaml
# .ship/pipelines/feature.yaml
steps:
  - id: implement
    agent: rust-runtime
  - id: gate
    agent: qa
    after: [implement]
  - id: merge
    after: [gate]
```

Each invocation is a **run** with status, ownership, and a completion signal. Steps emit events, and triggers can fan out from there.

## Agent Profiles

```jsonc
// .ship/agents/backend.jsonc
{
  "agent": { "id": "backend", "name": "Backend Engineer", "providers": ["claude"] },
  "skills": { "refs": ["tdd", "code-review"] },
  "mcp": { "servers": ["ship", "github"] },
  "permissions": { "preset": "ship-autonomous" }
}
```

| Preset | Mode | For |
|--------|------|-----|
| `ship-readonly` | plan | Reviewers, auditors |
| `ship-standard` | default | Interactive pairing |
| `ship-autonomous` | dontAsk | Dispatched agents |
| `ship-elevated` | dontAsk | CI and release automation |

## Registry

Skills and agent profiles are shareable packages. Packages are GitHub repos with a `.ship/` directory.

```bash
ship publish                   # publish your own
```

Every dependency is pinned in `ship.lock` with the exact commit and SHA-256 tree hash.

## Runtime

The daemon (`shipd`) is the runtime. It's event-sourced — every state change is recorded — and supervises agents through workspaces, sessions, and runs. Most of that is plumbing you don't write against directly; you author the seven primitives above and the runtime tracks the rest.

The daemon also serves the browser UI on `http://localhost:9315`, including the in-app Studios:

- **Agent Studio** — manage profiles, skills, servers, permissions
- **Skills Studio** — author and preview skill markdown
- **Views Studio** — author daemon-served views

Agents reach the runtime through MCP:

```bash
ship mcp serve          # stdio (wired via .mcp.json)
ship mcp serve --http   # HTTP for remote agents
```

## Service Mesh

Agents in a running Ship cluster discover and message each other through the runtime mesh. Supervisor primitives (spawn, channels, kill-tree) let pipelines coordinate beyond linear step ordering. The story here is still developing — expect the surface to evolve.

## Get Started

Ship is in **private beta** — there's no public installer yet. [Join the
waitlist](https://getship.dev/waitlist/) for access as the beta opens. When the
public beta lands, getting Ship will be a normal app install (a GUI installer or
your package manager); both pieces — the `ship` CLI and the `shipd` daemon —
register to start automatically, with setup opening in your browser on first run.

To run Ship today, build it from source.

### Build from source

You need a [Rust toolchain](https://rustup.rs) and [Bun](https://bun.sh).

```sh
git clone https://github.com/madvib/ship
cd ship
just build                 # builds the Rust binaries + bun workspace
```

`just build` is the canonical dev build. It produces the `ship` CLI and the
`shipd` daemon under `target/`. Start the daemon and open the browser UI:

```sh
cargo run -p shipd         # serves http://localhost:9315
```

### Dev install script

`scripts/install.sh` is an explicitly **developer / CI** path — it pulls a
release tarball, drops both binaries under the ship home's `bin/` dir, registers a
systemd-user or launchd service, and opens the setup wizard. It is not the
end-user distribution story; use it only for dev or CI bootstrapping.

```sh
curl -fsSL https://github.com/madvib/ship/releases/download/vX.Y.Z/install.sh | sh
```

Once the binaries are on your path:

```sh
cd your-project && ship use my-agent
```

## Status

Ship is in active development. The compiler, package manager, and CLI are stable. The runtime, daemon-served UI, and mesh are growing — breaking changes on that surface should be expected.
