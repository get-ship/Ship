# Implementation status

The architecture documented in this skill describes the **current** shape. Most of the framework has shipped; a small set of items remains in active development or deferred. This page is the honest map.

Updated as the implementation moves. If you find a drift between this page and reality, fix the page or fix the code.

## Stable (matches the doc)

- **`.sui` template directive set** — `<data>`, `<prop>`. Parsed by `crates/sui-compiler/`. The file IS the component; `<prop>` is a top-level directive alongside `<data>`. Reactive component state lives in the controller's `scope:` factory — the legacy `<state>` directive was retired and now produces a parse error. Tag = filename stem; shadow is always on; paired `.ts` controller is auto-detected. No per-component config file.
- **Control flow** — `{#if}`, `{#for key=}`, `{#match}`. Parsed and emitted; runtime support in `@ship/ui-runtime` and `@ship/ui-dom`. (Await blocks were considered and dropped — async flows go through `<data>` envelopes for server reads or a controller's `mount` for imperative work.)
- **Bindings** — `on:event`, `bind:value`, attribute interpolation, text interpolation. Stable.
- **Slots** — light-DOM resolution at mount. Stable.
- **`{#while-loading}` / `{#while-error err}`** — convenience boundary blocks. Stable. (Element forms `<while-loading>` / `<while-error>` were removed; block syntax only — see `template.md` and `ssr-hydration.md`.)
- **AOT compiler** — `crates/sui-compiler/` emits ESM + CEM + JSON schema. Stable.
- **Live envelope shape** — `LiveState<T> = { kind: 'loading' } | { kind: 'error', error: Error } | { kind: 'ok', value: T }`. Stable in `@ship/ui-runtime` (`live.ts`) and `@ship/ui-sdk-client`; consumed by views.
- **Envelope unwrap helpers** — `unwrap(sig): T | undefined` and `unwrapOr(sig, fallback): T` exported from `@ship/ui-runtime`. Replaces the per-derived `s.kind === 'ok' ? s.value : DEFAULT` boilerplate.
- **Reactive `<data>` source args** — daemon `/_sui/data?expr=...` accepts JSON-object args (`ship.git.diff({"commit":"abc"})`); SDK methods take typed args and serialize them into the URL.
- **Reactive re-subscribe** — `<data live>` source thunks receive `(ship, route, $scope)`; reading any signal inside the thunk is tracked by `live()`. When a tracked dep changes, the prior SSE subscription disposes and a new one opens with the updated args. Authors write `<data source="ship.X.Y({id: $scope.selectedId()})" live />` and the channel re-binds automatically when `selectedId` changes. Hydrate orders state-mount before data-mount so state signals are in scope by the time `<data>` evaluates.
- **Controller writable-proxy diagnostic** — when a handler writes `s.X` for a key not in the writable-state set (no signal of that name in the controller's `scope:` factory or compatible template-declared binding), the runtime warns explicitly (was silent failure). Catches the mix-up at first run instead of debug session #3.
- **Controller-owned state** — reactive component state lives in the controller's `scope:` factory; templates declare `<data>` subscriptions, props, and `<use-* as=>` aliases. The legacy `<state>` directive was retired and now compiles to a parse error pointing at the migration target.
- **Daemon auto-links `view.css`** — the HTML shell at `/sui/<name>` includes `<link rel="stylesheet" href="/_sui/views/<name>/view.css">`. Authors no longer hand-write the URL in their templates.
- **Template-scope generic on `controller<Scope>`** — declare the template-declared identifiers once as a `Scope` type, pass as the single generic, every section's destructure is typed without per-section annotations. `MutableState<Scope>` and `ReadonlyState<Scope>` are derived from `Scope` directly: scope keys whose values are `Signal<T>` become the writable state surface. The compiler emits a `<file>.sui.d.ts` declaration alongside each compiled template, exporting a `Scope` interface auto-derived from the template's `<data>` / `<prop>` / `<use-* as=>` elements. Import it as the controller generic to eliminate the manual `type Scope = { … }` declaration. Suppress with `--no-dts` if needed.
- **Three-role architecture as a typed contract.** `Controller`, `TemplateHook`, `ControllerHook`, `MutableState`, `ReadonlyState`, `ViewScope` in `@ship/ui-runtime` (`controller.ts`). Typed exports at the index. 17 type-level + behavior tests in `controller.test.ts`.
- **Six-section controller (scope / derived / on / use / mount / unmount).** Shape is enforced by `ControllerShape<Scope>`. The `scope:` factory is the single declaration site for reactive component state; legacy template `<state>` is gone. All six sections wired by the resolver and hydrate.
- **Three-tier controller (no controller / object / function).** All three accepted by `controller(def)` and the resolver. Tier 1 (no `.ts`) handled by hydrate's existing template-only path.
- **`controller(def)` runtime helper.** Wraps a def in a `{ setup, __def }` export drop-in compatible with `view()`. Daemon hydrate path unchanged. In `@ship/ui-runtime` (`controller-resolver.ts`).
- **Resolver — derived / on / use.** `resolveController(def, ctx)` consumes template-state signals from `ctx.scope` (identified by `ctx.stateKeys`), memoizes deriveds, namespaces `use:` hooks, wraps `on` handlers with a writable proxy whose `set` trap calls `.set()` on the underlying state signal and falls through to ambient scope (ship/route/navigate/template-data) on reads. Unit tests in `controller-resolver.test.ts` + e2e through hydrate in `controller-hydrate.test.ts`.
- **Lifecycle — `mount` / `unmount`.** Resolver attaches lifecycle as a non-enumerable `__shipSetLifecycle` property on the bindings record (won't leak into template scope). `hydrate` reads it, calls `mount(state, container)` after render, and calls `unmount(state)` before disposal. Errors in user code are caught and logged. The lifecycle's `state` is the writable proxy — handlers and lifecycle hooks see the same writable shape.
- **Per-section scope destructure.** Each controller section receives the merged scope. `derived` and hook factories see `{ ship, route, navigate, ...templateData, ...stateView, ...derivedView }`. Handlers see a writable proxy with the same fallthrough.
- **Mutation discipline as a type fact.** `derived` signature uses `ReadonlyState<Scope>` (callable getters over template-state keys); `on` handlers use `MutableState<Scope>` (assignable values for the same keys). Both types are computed from the `Scope` generic by selecting the keys whose values are `Signal<T>`. The compiler refuses `s.count = 5` in a derived without writing the right cast.
- **`packages/ui-components/`** with **19 SUI primitives** — `sui-status-dot`, `sui-spinner`, `sui-badge`, `sui-chip`, `sui-card`, `sui-link`, `sui-divider`, `sui-skeleton`, `sui-stat`, `sui-mark`, `sui-kbd`, `sui-avatar`, `sui-progress`, `sui-button`, `sui-tabs`, `sui-tab`, `sui-empty-state`, `sui-input`, `sui-terminal`. Each is shadow-DOM-by-default with scoped tone-matrix CSS. Bundled at `apps/shipd/assets/sui-components.js` and served at `/_sui/components.js`; the shell loads it side-effect so every `<sui-*>` tag is defined before any view renders. Library prefix `sui-` is the SUI library's permanent prefix; Lit primitives keep their `<ship-*>` prefix and the two coexist.
- **Component port helpers** — each component is a `<tag>.sui` (template + top-level `<prop>` directives + scoped `<style>`, no wrapper element) optionally paired with a `<tag>.ts` controller (`controller(def)`). Convention is the contract: directory IS the component, tag = filename stem, shadow always on, paired `.ts` auto-detected. Importing the package's `index.ts` side-effect loads each compiled `<tag>.compiled.js` — no runtime parser is involved. Test utilities (`createContainerRegistry`, `mount(reg, tag, attrs, innerHTML?)`, `flush()`) collapse the per-component test boilerplate.
- **Arc B-1 + B-2 — components AOT-compiled; `defineComponent` stub removed.** `sui-compiler` emits a `<tag>.compiled.js` per primitive at build time; the `<tag>.ts` side-effect imports it; the components bundle (`apps/shipd/assets/sui-components.js`) contains zero `hydrate(` calls and zero `@ship/ui-dom` imports. The B-1 transition stub at `packages/ui-components/src/define.ts` (a no-op `defineComponent` that logged a deprecation warning) is gone in B-2 along with its `index.ts` re-exports; the only remaining `@ship/ui-dom` reference inside the package is a vitest-only `*.compiled.js` shim for tests, which is not bundled.
- **Component runtime migration off `hydrate` (Phase G).** Components are fully AOT-compiled — registration runs from a compiled module's top-level `component(tag, …)` call at import time, never from a runtime template parse. The `sui-components.js` production bundle has zero references to `hydrate` or `@ship/ui-dom`. Parser exports are in `@ship/ui-dom/legacy` (Arc B-3); the production component bundle imports neither.
- **`views/agents/` ported to the new shape.** Subscription declared in template (`<data name="agents" source="..." live />`); controller has `derived: { items, total }` and `on: { newAgent }`. Bundled and served at `/sui/agents`.
- **Controller hooks (v1).** `useFilteredList`, `useSelection`, `useForm` ship from `@ship/ui-runtime`. 13 unit tests in `test/hooks/`. Each is a load-bearing UI pattern slice — no pre-emptive `usePagination`/`useSort`/`useTable`.
- **Template hooks (v1).** `<use-kbd>`, `<use-click-outside>`, `<use-shell>` ship from `@ship/ui-runtime`'s template-hook registry; `@ship/ui-dom` lifts `<use-*>` elements at parse time and invokes the registered factories during hydrate (after setup, before render). 6 e2e tests in `test/template-hooks.test.ts`.
- **Tree-sitter grammar + tmLanguage** — at `packages/sui-grammar/` and `apps/vscode/`. Stable.
- **LSP** — `packages/ui-lsp/` ships diagnostics, hover, completion. Stable for the directives + bindings it knows about. Recognizes `controller(def)` exports (Form C in `setup.ts`) — pulls section keys (scope / derived / on / use) into the template's scope-resolution. Reactive state identifiers come from the controller's `scope:` factory return; the LSP also reads the compiler-emitted `.sui.d.ts` for typed `<data>` / `<prop>` / `<use-* as=>` bindings. Knows `use:` namespacing — `{list.filtered()}` validates `filtered` as a contribution registered by the hook factory under the `list` alias; unknown members emit a diagnostic, hover surfaces the contribution's signature, and completion at `list.` lists the namespace's members. Surfaces a Warning when a `derived` section mutates state (`s.count = 5`). Completes `on:event={…}` braces against the controller's `on` keys with each handler's typed signature.
- **Eval rig** — `packages/ui-eval/` runs jsdom probes. Stable for the six task fixtures (easy/medium/hard). Prompt teaches `controller(def)` + the v1 hook surface; a controller-shape few-shot is included.
- **Renderable expression subset enforcement (Phase C).** `crates/sui-compiler/src/check/expr_subset.rs` walks every IR expression and refuses anything outside the subset documented in [ssr-hydration.md](ssr-hydration.md). Subset accepts identifier reads, literals, property access incl. optional chaining, `??`, arithmetic / comparison / boolean / unary `!`, ternary, template literals, array / object literals, zero-arg signal calls, and an allowlist of read-only methods (`slice`, `map`, `filter`, `includes`, `toString`, `length`, `keys`, `values`, `entries`). Wired into `compile()` after parse — non-renderable expressions fail at build time, not at first paint.
- **SSR walker — static rendering and marker emission (Phase D-1).** `crates/sui-compiler/src/render/` walks the IR and emits server-rendered HTML. Text interpolations emit `<!--sui:text:bN-->value<!--/sui-->` comment markers. Control-flow boundaries become `<sui-if key="bN">…</sui-if>`, `<sui-for key="bN">…</sui-for>`, `<sui-match key="bN">…</sui-match>` custom-element wrappers; inactive branches carry the `hidden` attribute. Author binding attributes (`on:click`, `bind:value`, `class:*`, `style:*`, `attr:*`) are preserved as-is with the binding key as their value (e.g. `<button on:click="b1">`). No `data-*` attributes in framework-emitted HTML. Stable `b<N>` keys allocated via a counter in source order. Public API: `render::render(program, opts) -> RenderOutput`.
- **SSR walker — initial scope evaluation and JSON island (Phase D-2).** Hand-rolled lexer + recursive-descent parser + AST evaluator under `render/eval/`. No JS engine dependencies. Walker builds an initial scope from `<data>` initial envelopes (`{ kind: "loading" }` for live), evaluates renderable-subset expressions against it, and inlines values into the rendered HTML alongside the markers. A single `<script type="application/json" id="__set_init__">` island carrying every initial data envelope is appended after the body. `RenderOutput` carries both `html: String` and `init: serde_json::Value`. Reactive component state declared in the controller's `scope:` factory has no SSR initial value — those identifiers stay unbound during static render and resolve at hydrate.
- **SSR walker — control-flow body rendering (Phase D-3).** Walker recurses into `{#if}` / `{#for}` / `{#match}` bodies when the discriminating expression evaluates cleanly against initial scope. Active branches are wrapped in `<sui-if key="bN">…</sui-if>` (or `<sui-for>`, `<sui-match>`); inactive branches emit `<sui-if key="bN" hidden></sui-if>`. The `hidden` attribute keeps placeholders invisible until the runtime activates them. `{#for}` iterations share inner keys via `KeyAllocator::snapshot/restore` so the binding manifest carries one entry per source position rather than one per iteration.
- **Compiler binding manifest (Phase E-prep).** Every compiled `.sui` ESM exports `export const bindings = [...]` parallel to the walker's `b<N>` keys. Each entry is `{ key, kind, expr, deps }`. `KeyAllocator` lifted to `crates/sui-compiler/src/keys.rs`; a new `bindings/` pre-pass walks the IR (every branch, regardless of SSR-time activation) building the registry. Walker consumes the registry by index, so emit and walker key allocation are parity-checked by `walker_keys_match_registry` integration tests.
- **`shipd` SSR walker debug endpoint (Phase F-1).** `GET /_sui/render/<view>` returns the SSR walker's HTML wrapped in a real `<!doctype html>` document with the importmap, components bundle, and an `attach()` boot script — fully interactive in a browser. `?format=json` returns `{ html, init }` for programmatic inspection. Stays in tree as the inspection surface alongside the production handler.
- **Attach-only client runtime — leaf bindings (Phase E v1).** `@ship/ui-dom` exports `attach(root, options)` that walks SSR-rendered DOM, reads the `__set_init__` JSON island, and wires leaf reactivity by querying `[on:*]`, `[bind:*]`, `[class:*]`, `[style:*]`, `[attr:*]` attribute selectors, `<!--sui:text:bN-->` comment markers, and `<sui-if>/<sui-for>/<sui-match>` boundary elements against the imported binding manifest. Returns a disposer that runs `unmount`, removes listeners, disposes effects, and closes SSE channels. 80+ tests across boundary recognition, every binding kind, lifecycle, and a counter-view e2e.
- **Attach runtime — control-flow swap (Phase E-2).** When a control-flow signal flips, the runtime POSTs the current scope state + boundary key to `/_sui/render-fragment/<view>`, receives the rendered subtree, and swaps the boundary's children. Recursively wires leaf markers on the new subtree (skipRoot so the boundary's own marker isn't re-wired). Inflight cancellation handles rapid signal flips. Compiler `render::render_fragment(program, registry, opts, init_overrides, key)` walks the IR but emits HTML only for the subtree at `key`. Full agents-view-e2e exercises the loading→ok branch swap.
- **Production demo view: `views/counter/`.** The canonical minimal shape from `examples.md`. A paired controller declares `count` via `scope: () => ({ count: signal(0) })`; the template has three inline arrow handlers (+ / - / reset) and `data-test` attributes for test rigs. Hittable at `/sui/counter` and `/_sui/render/counter` — fully interactive under SSR + attach.
- **Route-param reactivity (Arc C-1).** `route` is a `RouteSignals` from `@ship/ui-runtime`: `route.params.<name>` and `route.query.<name>` are lazy `Signal<string|undefined>`s, plus explicit `pathname` and `hash` signals. Reading any of them inside a `<data live>` source thunk, a `derived` body, or an `effect` registers the surrounding scope as a dep — when navigation updates the URL, the relevant signals fire and dependents re-run (the prior SSE subscription disposes; a new one opens with the updated args). Authors register the patterns they care about with `defineRoutes([{ pattern: '/agents/:id' }])`; reading `route.params.id` for an unregistered pathname returns `undefined` until a future navigation matches. Navigation is SPA-aware via `navigate(path, { replace? })`, which pushes to history and triggers a single global updater that all attached views observe; the `popstate` listener wires the back/forward path. The legacy `{ params, query }` record shape is still accepted by `attach()` (warns + upgrades) for one migration window.
- **`shipd` production SSR cut-over (Phase F).** `GET /sui/<view>` runs `sui_compiler::render::render_default` against the embedded `view.sui` source, wraps the SSR fragment + `__set_init__` JSON island in a document shell, and ships a boot script that calls `attach()` on `id="sui-root"`. Replaces the Phase 3 empty-shell + `hydrate(template, setup, …)` parse-on-the-client path. Views without control-flow reactivity (`views/counter/`) are fully interactive on first paint; views that gate behind control flow (`views/agents/`, `views/git/`) render the initial server-truth branch correctly (e.g. agents shows the `Loading agents…` while-loading branch from the `{kind:'loading'}` envelope) and become fully reactive once Phase E-2 lands the branch-swap. The shell preserves `id="sui-root"`, `data-view="<name>"`, and the legacy `<script src="/api/assets/ship-elements.js">` include so existing integrations (selectors, ported-but-unmigrated primitives) keep working.

- **`<use-*>` registry expansion.** Five new template hooks ship in `@ship/ui-runtime`: `<use-focus-trap>` (keyboard focus containment for dialogs), `<use-clipboard>` (click-to-copy with optional callback), `<use-title>` (reactive `document.title` binding), `<use-scroll-anchor>` (smooth-scroll to hash targets), `<use-intersection>` (IntersectionObserver callback). Full contracts in [hooks.md](hooks.md).
- **`@ship/ui-dom` legacy subpath (Arc B-3).** Parser exports (`hydrate`, `parseSetSource`, `directives/`) moved to `@ship/ui-dom/legacy`. The default `@ship/ui-dom` entry exposes only `attach`, `AttachOptions`, and `loadSetup`. The production `sui-dom.js` bundle is ≤ 4.8 KB gzip; the `build-bundles.mjs` CI gate enforces a 9 KB ceiling and asserts zero `parseSetSource` references in the production bundle.
- **Compiler-emitted `.sui.d.ts` per template.** The `sui-compiler` emits a `<file>.sui.d.ts` declaration alongside each compiled template. The file exports a `Scope` interface auto-derived from the template's `<data>`, `<prop>`, and `<use-* as=>` elements. Import it as the `controller<Scope>` generic to eliminate the manual type declaration entirely. Suppress with `--no-dts` if needed.
- **Tier-1/tier-2 threshold rule (compile diagnostic).** A multi-statement `on:event` handler body in a tier-1 template (no paired `.ts`) is a build-time error: `multi-statement handler — paired controller required for tier-2 work`. Single-expression handlers and single-statement blocks are fine at tier 1. The check is skipped entirely once a `.ts` exists. See [controller.md](controller.md) for the full rule.
- **`<form mutation>` mutations primitive.** `<form mutation="ship.X.Y">` is the platform mutation primitive for write operations. The compiler wires it at compile time (JS-attached path: `wireFormMutation(formEl, 'ship.X.Y', $scope)` in the compiled module). The daemon's `POST /_sui/mutation/{view}?form=<key>` endpoint handles the progressive-enhancement path when JS is absent: validates the form key, resolves the SDK chain from the binding manifest, dispatches the call, and redirects back to Referer. In either path the `$mutation` signal is exposed in view scope with the standard `{ kind: 'loading' | 'ok' | 'error' }` envelope. `success` and `error` CustomEvents bubble from the form for `on:success` / `on:error` handlers.
- **QA e2e Playwright suite.** `tests/e2e/` contains Playwright-based end-to-end coverage for `counter`, `agents`, and `git` views (24 tests total). Exercises SSR correctness, `attach()` wiring, signal mutations, SSE-driven boundary swaps, and tab-switching reactivity. Run with `just qa-e2e` (requires a running daemon). See [e2e-testing.md](e2e-testing.md).

## In active development
- **Rust compiler awareness of `<use-*>`.** The Rust AOT compiler at `crates/sui-compiler/` doesn't yet lift `<use-*>` elements to its IR — only `<data>` and `<prop>` are recognized as directives. Today this isn't an issue because the daemon parses `.sui` source via the JS dom interpreter, not the AOT output. Becomes a gap when the compiler's output enters the production path.
- **Eval rig grades against the new shape.** Prompt teaches `controller(def)` and the new section vocabulary; few-shots include both pure declarative and a controller-shape example. `usePagination` / `useSort` / `useTable` controller hooks are deferred — added the first time a real view needs them, not before.
- **LSP awareness of `controller()` semantics.** LSP recognizes the export shape and extracts top-level section keys (good — `s.count`, `incr`, `total`, `list` all resolve in template scope). Remaining gap: the LSP re-derives view scope from source rather than reading the compiler-emitted `.sui.d.ts`; a follow-up wires the d.ts read path.

## Removed shapes (formerly here, now gone)

- **`view()` factory.** The original `view<Bindings>(setup)` factory is gone. Every shipped view (just `views/agents/`) is on `controller()`; the precursor wrapper, its tests, and the LSP's Form A type-arg extraction were removed.
- **`.ship` SFC three-block format** and **sail-era script-block syntax** (`prop X: T = default`, `mount {}`, `effect on X`) — never made it to a working compiler under the current framework. See the phased-out `ship-components` skill for what was there.
