Ship · design system · where things live

Component taxonomy

sui-* = the framework-general vocabulary · ship-* = Ship's own packs. Everything publishes. Runtime dependency is always ship. A domain is just a pack.

Classifier 1 — the prefix

Generality

sui-* — generic, useful to anyone on SUI. ship-* — Ship-flavored: composed, themed, engine-wrapped, or runtime-bound. Both publish as packages.

Classifier 2 — the folder

Tier

Library you compose with → components/. Product you deploy → views/ + scaffolds/. Prefix and tier cross-cut — different questions.

The rules — one hard, the rest soft

  • hardRuntime dependency ⇒ ship-*. The only non-negotiable line.
  • promotePure-sui & reused by 2+ ship packs ⇒ graduate it into a sui element pack.
  • softAnything without a runtime dep — placement is refactorable. Don't agonize over the seam (canvas, media).
  • modelA domain is just a pack. No special folder, no separate tier.
  • cadenceWe deliver by domain — that's sequencing, incidental to this structure.
