When to use

Trigger this skill when the planner detects an opportunity to add or modify behaviour that benefits from a written test before implementation. Surface it via the launcher under testing.

Steps

  1. Read the surrounding context (file, diff, or selection). Identify the smallest observable behaviour that should change.
  2. Write a failing test that asserts the desired behaviour. Run the suite; confirm the test fails for the right reason.
  3. Implement the minimum change required to turn the test green. Avoid anticipating future cases — strict minimum.
  4. Re-run the suite. On green, refactor — both the implementation and the test, if either is unclear.
  5. Emit test-plan.md summarising what was added, with one section per assertion.

Inputs

  • target — file or symbol to drive tests against.
  • strict — when true, fail the run on any unreviewed change.

Outputs

One markdown artifact under .artifacts/test-plan.md.
