## 2. Classification

### Bucket A — Chrome (subsumed by SUI elements)

These wrap `<ship-*>` web components with j2-ergonomic defaults. No Rust handler ever calls them directly; no `.ship/views/` template currently includes them.

| Templates | LOC |
|---|---|
| `_breadcrumb.html.j2` | 16 |
| `_empty.html.j2` | 23 |
| `_error.html.j2` | 15 |
| `_loading.html.j2` | 15 |
| `_toast.html.j2` | 19 |
| `_toolbar.html.j2` | 25 |
| **Total** | **113** |

SUI views use the underlying elements directly in `.sui` templates. For j2 view authors these provided ergonomic wrappers, but no current `.ship/views/` template uses them (confirmed by grepping all `.html.j2` files in `.ship/views/`). The tests in `templates_tests.rs` verify `_empty.html.j2` is syntactically valid but do not represent a runtime dependency.

These are v1 view definitions baked into `shipd` that were superseded when the `.ship/views/` extension-point system launched. All three view trees (chat, events, settings) have active equivalents in `.ship/views/` with SUI-ported counterparts in `views/`:

## 3. Retirement Plan

### Phase 1 — Immediate (no dependencies, no SUI parity gap)

**Retire all of Bucket E (14 templates, 519 LOC):**

The `.ship/views/` successors are already live. The SUI ports (`views/chat/`, `views/events/`, `views/settings/`) have shipped as of batch A–D. The bucket E templates are unreachable — no handler renders them and no live view includes them.

Steps:
1. Delete the 14 template files.
2. Remove the corresponding 14 `include_str!` + entry pairs from `views/templates.rs:TEMPLATES` (lines 111–165).
3. Verify `just build` passes — the deleted names were only registered, not called.
4. The `templates_tests.rs` round-trip tests use `render_view_source`, not `render`, so they are unaffected.

LOC reduction: **−519** in `templates/` + **−28** in `views/templates.rs`.

### Phase 2 — After confirming no user-authored j2 views use them

**Retire Bucket A chrome partials (6 templates, 113 LOC):**

Prerequisite: confirm no user-authored `.ship/views/` file anywhere includes `_breadcrumb`, `_empty`, `_error`, `_loading`, `_toast`, or `_toolbar`. Current grep of the checked-in `.ship/views/` tree shows zero uses. If user config ships these in their own `~/.ship/views/`, that is not detectable from this repo.

Recommended check before retiring: document removal in CHANGELOG and do one release cycle of deprecation notices.

Steps identical to Phase 1 for the remaining 6 entries in `TEMPLATES`.

LOC reduction: **−113** in `templates/` + **−12** entries in `TEMPLATES`.

### What stays (permanent or long-lived)

| Template | Reason to keep |
|---|---|
| `_page_shell.html.j2` | Required by canvas; can retire once canvas migrates to `view-host` or a custom shell |
| `_raw_shell.html.j2` | Active path; `/api/v1/view/{name}/raw` is part of the Studio iframe protocol |
| `_ship.html.j2` | Backbone of j2 view system; retires only when j2 views retire |
| `_urls.html.j2` | Auto-generated; retires only when `routes.rs` drops the jinja codegen target |
| `canvas/blank.html.j2` | Active; retires when view-session framework is migrated to SUI |
| `canvas/artifact.html.j2` | Active; same as above |

**Projected LOC after both phases:** 2,133 − 519 − 113 = **1,501** (−30%).  
After Phase 1 alone: 2,133 − 519 = **1,614** (−24%).

## 4. Open Questions

1. **Canvas template name normalization.** Tests pass `"canvas/blank"` (no `.html.j2` suffix) to the view-session open endpoint, but `TEMPLATES` registers `"canvas/blank.html.j2"`. It is unclear whether `shell_context` or the open-handler normalizes the name before `templates::render`. This could be a latent bug where the render silently fails. Worth confirming before any canvas work.

2. **User-global `~/.ship/views/` coverage.** The audit grepped only the repo's `.ship/views/`. If any user or integration ships a `~/.ship/views/` directory that includes the chrome partials (`_empty`, `_error`, etc.), Phase 2 retirement would break them silently. A deprecation notice or a runtime warning on partial inclusion would mitigate this.

3. **`_page_shell.html.j2` migration path.** Once canvas sessions are common enough to care about, it may be worth migrating `canvas/blank.html.j2` and `canvas/artifact.html.j2` to use a dedicated lightweight shell (or `view-host`) rather than the j2-based `_page_shell`. This would unblock retiring `_page_shell` and reduce the templates layer to just the SDK macros + URL macros.

4. **`_ship.html.j2` sunset horizon.** The macro library is 1,163 LOC and is the dominant remaining mass in `templates/`. There is no current migration plan for converting active `.ship/views/` j2 views to SUI. Until that plan exists and ships, `_ship.html.j2` is non-negotiable.
