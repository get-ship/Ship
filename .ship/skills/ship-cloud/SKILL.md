# Ship Cloud

Cloud backend for Ship — event sync, team coordination, analytics. Lives under `cloud/` in the monorepo. Deploys to Cloudflare Workers + Durable Objects.

## Architecture

Two-tier, nothing else.

- **Gateway** (`cloud/apps/gateway`) — Hono Worker. Auth, routing, CORS. **Zero business logic.** Validate input, enforce auth, forward to a DO via RPC, return the result.
- **PlatformDO** (`cloud/apps/actors/platform`) — one per project. Workspace list, job queue, config events. Owns platform-scoped state.
- **WorkspaceDO** (`cloud/apps/actors/workspace`) — one per workspace. Actor, session, skill events. Created on demand by the platform DO.

Shared transport types live in `cloud/packages/types` — generated from the Rust runtime via `cargo xtask gen-types`. Do NOT hand-edit `cloud/packages/types/src/generated.ts`.

## Patterns

- **Hono** for gateway routing. Middleware chain: `onError` → `auth` → route handler.
- **Durable Objects + Drizzle ORM** over DO SQLite. Schema in `src/data/schema/**/*.ts`, migrations in `migrations/` (generated via `pnpm --filter @ship-cloud/platform schema:generate`).
- **RPC facades** for DO method exposure. Each DO class exports facade classes (SyncFacade, JobsFacade, etc.) that the gateway calls across the RPC boundary.
- **Repository pattern** for data access. Each DO has `src/repositories/*.repository.ts` that wrap Drizzle queries and return `Result<T>`.
- **Projection repositories** translate inbound events into row updates (`session-projection.repository.ts`, `actor-projection.repository.ts`).
- **`Result<T>`** for error handling — no thrown errors across the RPC boundary.
- **Vitest with `@cloudflare/vitest-pool-workers`** for testing. Use `runInDurableObject` for DO isolation.

## Event envelope

The canonical `EventEnvelope` type and all event-type string constants live in Rust at `crates/core/ship-types/src/{envelope.rs, event_types.rs}`. The TS mirror in `cloud/packages/types/src/generated.ts` is regenerated by `cargo xtask gen-types`.

**Rule:** If cloud needs a new event field, add it in Rust first (with a `specta::Type` derive), regenerate, then commit both sides. Never hand-edit the generated file.

CI check: `cargo xtask gen-types --check` fails if the generated files are stale.

## Rules

- Gateway has zero business logic. Validate input, enforce auth, forward to DO.
- DOs own their data. No shared state between DOs except through events.
- Event envelope matches the Rust runtime type exactly — enforced by codegen.
- Tests use `runInDurableObject` for DO isolation.
- No deployment config yet — local dev only. Wrangler configs are present but production secrets + bindings are not wired.

## Known drift (as of import)

The `PLATFORM_EVENT_TYPES` / `WORKSPACE_EVENT_TYPES` groupings in `cloud/packages/types/src/events.ts` contain several constants the Rust runtime does not emit (e.g. `session.completed`, `actor.updated`, `actor.deleted`). Projection branches switching on these cases never match. Before adding new projection logic, check whether the event is actually emitted by Rust — look in `crates/core/ship-types/src/event_types.rs`.

## Local development

```bash
# From repo root, types sync
cargo run -p xtask -- gen-types

# Per-package tests (once wrangler/vitest/drizzle-kit are wired at the workspace)
pnpm --filter @ship-cloud/gateway test
pnpm --filter @ship-cloud/platform test
pnpm --filter @ship-cloud/workspace test

# Regenerate DO migrations after schema edits
pnpm --filter @ship-cloud/platform schema:generate
pnpm --filter @ship-cloud/workspace schema:generate
```

## When to use this skill

- Writing or reviewing code under `cloud/`
- Adding a new event type — follow the envelope flow (Rust → codegen → cloud)
- Adding a new DO facade or repository
- Debugging sync failures between runtime and cloud
- Extending the gateway with a new route
